# 📝 版本更新记录

## v1.2.7

#### ✨ 新增功能
- **乐迷团播放任务解耦与独立会话控制 (`fansgroup.webSession`)**：
  - 将乐迷团任务从通用 `play.webSession` 配置中解耦，在 `fansgroup:` 配置段新增独立的 `webSession: false` 开关；
  - 因网易云机制，乐迷团「播放歌曲」任务必须使用网页端会话（剔除 `os` cookie）才能获取带 `authSecret` 的媒体链接并计入任务进度；
  - **空跑拦截保护**：未开启 `webSession` 时，乐迷团自动跳过播放歌曲任务并输出日志提示，避免无效播放和等待；点赞、分享、发动态、原创度加速等其他任务不受影响照常执行；
  - WebUI 系统配置管理中同步增加对应配置开关与说明。
- **WebUI 在线更新与状态感知优化**：
  - 彻底优化 WebUI 系统设置中的版本更新交互，解决此前检测到新版本后更新按钮被意外隐藏的问题；
  - **状态自适应主操作按钮**：
    - 检测到新版本待下载时，展示蓝色的「立即更新」按钮；
    - 新版本后台下载就绪后，按钮自动变为醒目的绿色「立即重启生效」大按钮，更新徽章明确显示为「待重启」；
  - **一站式更新流转**：点击「立即更新」下载完成后，自动弹窗询问是否立即重启生效，支持一键完成升级；
  - **重启服务探测与自动重载**：重启后前端以 1 秒为间隔轮询健康检查接口，探测到新服务重新拉起后自动刷新页面展示全新版本。
- **空闲自动热重启与运行任务安全防护 (`updater.auto_restart`)**：
  - 新增 `updater.auto_restart: true` 配置项（默认开启），适用于 Linux、Windows 单文件及 Docker 容器环境；
  - **全无人值守热升级**：新版本静默下载就绪后，系统后台自动监控任务运行状态，仅在**系统处于完全空闲（无运行中且无排队任务）**的时段自动平滑热重启完成升级；
  - **长任务误杀保护**：若当前有任务正在执行（如大批量刷歌、长耗时日推播放等），系统会保持静默待命，绝不强行打断正在跑的任务，直到所有任务全部平稳结束后再自动重启；
  - 手动触发重启时增加并发安全检测，若有正在运行的任务会弹窗明确预警任务数量，需二次确认后方可强制重启。
- **插件中心新增「在线插件市场 / 在线插件仓库」**：
  - 在插件中心首页顶部新增二级 Tab 切换（【已安装插件】vs【在线插件市场】）；
  - 精选内置生态插件：
    - `crossgg/ncmm-qqbot`：基于腾讯官方 QQ 机器人 API v2 的常驻伴生插件，支持 QQ 私聊自动更新 Cookie、扫码登录与通知中继推送；
  - **一键极速在线安装**：在市场卡片中直接展示开源仓库、作者、版本、特性标签与详细描述，支持选择 GitHub 镜像加速通道并一键下载安装；
  - **智能安装状态感知**：自动匹配本地已安装插件，已安装插件显示「已安装」并提供「前往管理」快捷入口，未安装插件支持一键直接安装。
- **插件在线检测更新与一键平滑升级**：
  - **免 API 限流的轻量探测**：通过向 `releases/latest` 发送轻量 HEAD 请求并拦截 302 重定向获取最新 Tag，完全绕过 GitHub REST API 60次/小时 的严格限流，杜绝 IP 被封风险，并无缝支持镜像加速；
  - **24 小时本地长缓存 + 60s 主动防抖**：默认 1 天至多静默联网探测 1 次，其余访问直读本地缓存文件，0 额外网络开销；已安装列表工具栏提供「检查更新」按钮，手动触发后提供 60 秒倒计时防抖；
  - **版本升级直观感知与一键升级**：已安装卡片与在线市场卡片均支持直观展示「⬆️ 可更新 vX.X.X」醒目徽标，并提供「一键升级」按钮；
  - **用户配置保护与 Windows 文件锁防护**：在线升级解压更新包时严禁覆盖现有的 `config.yaml` 配置文件；升级常驻后台守护插件时，自动安全停机释放 Windows 下的 `.exe` 独占文件锁，升级完成后自动恢复运行状态。
- **QQ 机器人生态接入支持**：
  - 支持配套 QQ 机器人插件生态无缝联动，可在插件中心在线市场直接一键安装或查看主页：[crossgg/ncmm-qqbot: ncmm 配套 qqbot 插件](https://github.com/crossgg/ncmm-qqbot)。

#### 🐞 Bug 修复
- **修复 Docker 镜像云构建 `/cmd` not found 报错**：
  - 修复根目录 `.dockerignore` 缺少 `cmd` 目录白名单导致 Docker 构建上下文缺少 launcher 源码、触发 `failed to compute cache key: "/cmd": not found` 的问题。
- **修复插件中心常驻后台守护插件无法启动的问题**：
  - 修复常驻后台插件（`type: daemon`）在特定相对工作路径下启动时找不到执行入口二进制文件的问题。

## v1.2.6

#### ✨ 新增功能
- **插件中心支持常驻后台插件**：
  - 插件体系新增支持 `type: daemon` 常驻后台守护类型，WebUI 启动时自动按配置拉起后台插件，服务退出时向守护进程发送信号优雅停机；
  - 插件卡片支持展示运行状态，并提供启动、停止与重启控制；定时任务调度选择中自动区分并过滤常驻类插件。
- **定时任务加入随机延迟设置**：
  - WebUI 定时任务支持设置「运行前随机延迟」（单位：秒，最大延迟秒数）；
  - 任务触发时将在 0 至设定秒数区间内随机休眠后再执行命令，有效分散并发请求峰值并降低风控风险。
- **Docker 容器内热更新与 Launcher 架构**：
  - 引入极轻量守护启动器 `ncmm-launcher`（作为容器 PID 1 托管主程序），默认开启内容器自更新能力；
  - 支持直接在 Docker 容器内部检测并下载新版本，无需频繁手动拉取镜像或重建容器，体验与独立二进制运行完全一致；
  - 持久化运行目录管理（`/data/runtime/`），自动保留当前运行版本与最近 1 个历史备份版本；
  - **健康探测与防变砖自动回滚**：新版本启动后进行 30 秒健康检查探测，若启动崩溃或接口异常，自动切回上一版本重新拉起，保障容器永不挂死；
  - **镜像升级保护**：后续在宿主机通过 `docker compose pull` 更新基础镜像时，Launcher 会智能比对内置版本，若镜像版本更新会自动平滑切回镜像内置版；
  - WebUI 系统面板新增「立即更新」按钮，支持一键下载并在重启后秒级热切换。
- **插件在线安装加速服务支持**：
  - WebUI 插件在线安装弹窗新增「下载加速服务」选项，默认首选直连 GitHub，并预置常用公共加速镜像（`gh-proxy.com`、`ghproxy.net`、`githubproxy.cc`），同时支持自定义加速代理前缀；
  - 命令行 `ncmm plugin install` 同步支持 `-p, --proxy` 参数；
  - 加速代理下载失败时支持自动回退直连重试。

#### 🐞 Bug 修复
- **修复在线安装失败的 bug**：
  - 修复 WebUI 在线安装插件时输入完整 GitHub 仓库链接报 `target URL or repo is required` 的参数解析问题；
  - 规范前后端仓库标识与下载 URL 转换逻辑，支持标准 GitHub URL 与 `owner/repo` 两种格式，并完善私有库 Token 支持。
- **修复用户名和歌手名不一致时无法跳过本人歌曲的 bug**：
  - 升级 `isSelfSong` 歌曲归属判定算法，针对认证音乐人账号获取并比对真实的音乐人歌手 ID（`ArtistId`）；
  - 精确比对歌曲详情中所有参与歌手的 ID（遍历 `detail.Ar`），只要包含当前账号歌手 ID 即准确识别并排除，即使合作歌曲或用户名与音乐人昵称不一致也能精准跳过，避免无效刷歌。
- **修复 Docker 容器内任务执行版本滞后问题**：
  - 新增容器内智能包装脚本 `/usr/local/bin/ncmm`，cron 计划任务与 CLI 临时命令自动优先执行当前在线更新的最新二进制文件。

## v1.2.5

#### ✨ 新增功能
- **强制升级机制（由发布方按版本声明）**：发布方可在某个 release 的正文里用一行隐藏标记（`<!-- ncmm-force-upgrade -->`）声明"该版本必须升级"。**只有被显式声明的版本才会生效，普通更新完全不受影响**。命中并过了宽限期（默认从发布时间起 1 个月）后，业务命令会被拦截，并明确提示当前版本、要求版本、升级原因与升级方式（退出码 `3`）；`update` / `version` / `web` / `login` / `auth` / `help` 始终可用，随时可以自救。WebUI 会整站替换为升级提示页，并拒绝启动任何任务（含定时任务）。宽限期内只打印一行提醒；联网失败、状态文件缺失或损坏时一律放行，不会因为网络问题把用户锁死。
- **黑胶会员赠送支持按角色区分**：新增 `vipMemberGift.enableGiftSecondaries`（默认 `false`），默认只让主账号把可赠送的会员天数发布到云端互助池，避免小号的会员天数被无意消耗；需要恢复"辅助账号也赠送"时把该项设为 `true` 即可。命令行单独指定 `--cookie-file` 时按主账号处理。

#### 🐞 Bug 修复
- 修复黑胶会员领取遇到失效赠送卡时反复重试的问题：`12200 非法的邀请token` 这类"卡本身已失效"的失败，此前被归类为可重试的普通失败，云端不会作废该卡，导致同一张坏卡继续被发给其他账号；现在会归类为终态 `invalid` 直接作废，自建云端服务（`tools/vip_member_gift_cloud`）也做了相同兜底判定。
- 修复黑胶会员领取接口返回成功但时长为空时不上报失败的问题：该情况下一次重试会原样取到同一张卡，把 5 次重试机会全部浪费在同一张坏卡上；现在会记录失败并继续匹配下一张。
- 修复黑胶会员领取在未配置 `accounts.antiCheatTokens` 时被直接跳过的问题：领取接口实测不校验该 Token，现在只打印一行提示后继续进行领取，网页版扫码登录得到的 Cookie 也能直接领取（每日推歌仍按要求需要配置该 Token）。
- 修复 `ncmm update --apply` 必须先手动执行一次 `ncmm update` 才能应用更新的问题：现在它会自己先检查一次，可独立使用；已经是最新版本时以成功状态结束并提示"当前已是最新版本，无需更新。"（此前会报错），同时在替换前清理上次遗留的 `.old` 文件，避免个别系统上重命名失败。
- 修复乐迷团「播放歌曲」任务不计数的问题：新增 `play.webSession`（默认开启），播放链路使用网页端会话（剔除 `os` cookie，服务端才会下发带 `authSecret` 的媒体地址）；乐迷团播放日志改为真机网页端形态并上报到 `clientlogusf` 域名、音频改为完整下载，同时去掉无意义的整首等待（2 首由约 6 分钟缩短到约 15 秒）。
- 刷歌类任务（`playids` / 云贝日推播放 / 音乐人有效播放）仅同步会话处理：同样在播放请求中剔除 `os` cookie；**上报内容、上报域名与整首时长等待逻辑保持原样**，不改变刷歌节奏。
- 黑胶任务「每日听3首VIP歌曲」不再尝试执行：实测其计数只走 App 端专有通道（6 组对照实验均无法推进进度），现改为提示需在 App/手机内手动完成，避免白等约 10 分钟。

#### 💫 体验优化
- 面板更新脚本（`scripts/ncmm-update.py`）不再自带一套版本判断与下载规则，改为进入程序目录调用 `ncmm update --apply`，更新规则与程序自身完全一致，不会再出现两边规则不一致的情况；仅在目录中没有 ncmm 二进制（首次安装）时才由脚本下载安装包，更新失败时会自动释放被占用的进程后重试一次。

#### 📚 文档更新
- 更新 `config.yaml`、`docs/configuration.md`、`docs/cli.md` 与 WebUI 配置项说明中关于黑胶会员领取、`antiCheatTokens` 的描述，明确"领取不需要 Token、每日推歌需要"。
- 云端互助服务 README 补充 `POST /tokens/fail` 的 `reason` 取值与终态语义说明。
